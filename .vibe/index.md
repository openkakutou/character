# character — Codebase index

## Modules
- [`modules/root.md`](modules/root.md) — entry point; assembles `air`/`def`/`sff`/`cns` data into a single `Character` struct, with frame-to-sprite resolution via `ResolveSprite` and a full `.def`-driven load via `Load`, completing the full read surface across all four MUGEN/Ikemen file formats
- [`modules/air.md`](modules/air.md) — `.air` animation read and write paths: pure-data model (`Animation`, `Frame` with `IsBlank()`, `ClsnBox`), a `Parse` function reading `.air` text into it (now accepting the `-1` blank-frame sentinel), a `Serialize` function writing it back out, a `Document`/`ParseDocument` pair for byte-exact, comment-preserving round trips of unmodified files, and a `SpriteResolver` resolving each `Frame`'s sprite reference against sprites loaded via `sff` — recognizing a blank frame directly instead of attempting a lookup
- [`modules/sff.md`](modules/sff.md) — `.sff` sprite handling: version-agnostic read-path `Sprite`/`SpriteGroup` structs and a `Load` entry point assembling a full file (either version, auto-detected) directly into them; v1 read path `ParseV1`/`DecodePCX` (header/sprite table, RLE-compressed PCX pixel decoding); v1 write path `SerializeV1`/`EncodePCX`, completing the v1 read+write cycle; v2 header/sprite/palette-table read path `ParseV2`; v2 read+write pixel handling for raw/PNG sprites (`DecodeV2Sprite`/`EncodeV2Sprite`) plus the full v2 file write path `SerializeV2`, completing the v2 read+write cycle for that format scope; `DecodeV2Sprite` now also decodes the run-length-compressed `V2FormatRLE8` format and the dictionary-compressed `V2FormatLZ5` format — the latter validated to decode correctly against 6086 real LZ5 sprites from a local character corpus, and notably ignoring `ColorDepth` (real LZ5 sprites declare it as 5, not 8) unlike every other indexed format (encode side not yet extended to match either); a palette index-to-RGBA resolution helper (`ResolvePixels`/`Palette`, plus version-specific `DecodeV1Palette`/`ResolveV1Palette` and `DecodeV2Palette`/`ResolveV2Palette`), kept separate from the pure-data sprite/pixel-buffer types; RLE8/LZ5/RLE5 encode and RLE5 decode still pending
- [`modules/def.md`](modules/def.md) — `.def` character definition read and write paths: pure-data `CharacterInfo` (name, author, and referenced file paths per `.def` section), a `Parse` function reading `[Info]`/`[Files]` text into it while skipping unrecognized sections/keys, a `Serialize` function writing it back out, and a `Document`/`ParseDocument` pair for byte-exact, comment-preserving round trips of unmodified files — completing the `def` read+write cycle; wired into `Character` via the root package's `Load`
- [`modules/cns.md`](modules/cns.md) — `.cns` combat logic read and write paths: pure-data model `StateDef` (a Statedef header plus its `Controller`s) and `Controller` (a state controller stored as unevaluated `Triggers`/`Parameters`), plus `StateType`/`MoveType`/`PhysicsType` enums, a `Parse` function reading `[Statedef N]`/`[State N]` text into them, a `Serialize` function writing it back out, and a `Document`/`ParseDocument` pair for byte-exact, comment-preserving round trips of unmodified files — completing the `cns` read+write cycle; wired into `Character` via the root package's `Load`

## Observed patterns
- Root package (`character`) is a thin assembly layer over format-specific sub-packages (`def/`, `sff/`, `air/`, `cns/`) — it composes `air.Animation`/`sff.SpriteGroup`/`cns.StateDef` into `Character`, delegates frame-to-sprite resolution to `air.NewSpriteResolver` rather than reimplementing it, and loads a full `Character` directly from a `.def` file path (`Load`) by delegating to `def.Parse`/`air.Parse`/`sff.Load`/`cns.Parse` in turn rather than reimplementing any of their file-reading logic — completing the roadmap's full read surface across all four formats; `air/` now has a data model, a read-path parser, a write-path serializer, a format-preserving `Document` type, and a `SpriteResolver` resolving frame references against loaded sprites; `sff/` now has its read-path data model, a version-agnostic full-file loader (`Load`) that finally performs the "later assembly step" earlier ADRs deferred, a complete v1 read+write cycle (`ParseV1`/`DecodePCX`, `SerializeV1`/`EncodePCX`), a v2 header/table read path (`ParseV2`), and a complete v2 read+write cycle for raw/PNG sprite formats (`DecodeV2Sprite`/`EncodeV2Sprite`, `SerializeV2`), with `DecodeV2Sprite`'s decode side now additionally covering the RLE8 and LZ5 compressed formats (their encode counterparts and the remaining RLE5 format still pending), and a palette index-to-RGBA resolution helper (`ResolvePixels`/`Palette`, plus version-specific `DecodeV1Palette`/`ResolveV1Palette` and `DecodeV2Palette`/`ResolveV2Palette`); `def/` now has a complete read+write cycle too (`CharacterInfo`, `Parse`, `Serialize`, `Document`/`ParseDocument`), matching the "data model before parser" order `air`/`sff` followed, and is now wired into `Character`; `cns/` now also has a complete read+write cycle (`StateDef`, `Controller`, `StateType`/`MoveType`/`PhysicsType`, `Parse`, `Serialize`, `Document`/`ParseDocument`), matching the same "data model before parser" order `air`/`def` followed, and is now wired into `Character` too, via `Load`'s `ConstantsFile` reference — real-world `.cns` files spot-checked against a local corpus during that wiring showed `cns.Parse` rejecting a majority of them (state headers with non-numeric/missing numbers, header fields holding MUGEN expression syntax instead of literal integers), a pre-existing gap in `cns.Parse` itself, out of this wiring item's scope.
- `cns.Controller` stores its trigger conditions and parameters as untyped, unevaluated data (`[]string`/`map[string]string`) rather than controller-type-specific fields — the same "read-path model can't hold everything yet" reasoning `air`/`sff`'s low-level types followed, but here the driver is scope (no expression engine exists yet), not a format-shape mismatch. See an explicit ADR.
- `sff.Load` (and, transitively, `character.Load`) resolves the "meaning is version-defined" ambiguity `Sprite.Palette`'s doc comment left open: for v1, which only records a per-sprite "reuses previous sprite's palette" boolean on disk, it derives a numeric value via a running counter (incremented on every non-shared sprite, inherited by sharing sprites) rather than leaving every v1 sprite at a constant placeholder; for v2, the table already has a real numeric palette bank index, so it's used as-is with no derivation needed. Referenced `.def` file paths (`.air`/`.sff`) are resolved against the `.def` file's own directory, not the process's working directory. See an explicit ADR.
- `def.Parse` follows the same "read-path model can't hold everything, so drop what it can't represent" pattern as `air.Document`'s split (per an explicit ADR): unrecognized `.def` sections are skipped rather than erroring or being smuggled onto `CharacterInfo`; `def.Document`/`def.ParseDocument` are that write path's format-preserving counterpart, mirroring `air.Document` exactly — including the same limitation that it only guarantees byte-exact preservation for *unmodified* content, not regeneration around edits.
- `cns.Parse` extends `def.Parse`'s "skip unrecognized sections" tolerance one step further: a bracket line that isn't a `[Statedef N]`/`[State N]` header is skipped without validation (same as `def.Parse`'s unknown `.def` sections), but a bracket line that *looks like* an attempted Statedef/State header yet fails to parse (missing/non-numeric state number) still returns a line-numbered error rather than being silently skipped — distinguishing "genuinely unrelated content" from "a typo in the two header shapes this parser is responsible for". See an explicit ADR.
- `cns.Serialize`/`cns.Document` mirror the `def` write path exactly: `Serialize` always writes fresh text (a semantic round trip through `Parse`, not byte-exact preservation), while `cns.Document`/`ParseDocument` is the separate format-preserving type guaranteeing a byte-exact round trip for *unmodified* content only, per the same explicit ADR `air`/`def` already followed. Because `Controller.Parameters` is an unordered map and `Triggers` never records which `trigger1`/`trigger2`/`triggerall` key produced it, `Serialize` renumbers `Triggers` sequentially and sorts `Parameters` by key for deterministic output rather than attempting to reconstruct the original key names — a distinction `cns.Parse` already discards on read, not a new loss introduced by the write path.
- Tests are co-located with source as `*_test.go`, one behavior per test function, named `Test<Type>_<Condition>_<Expectation>`.
- Read-path data types (e.g. `air.Animation`/`air.Frame`) store already-resolved values (e.g. per-frame collision boxes) rather than the file format's own authoring shortcuts (e.g. default/override) — parsing concerns stay out of the pure-data model, per an explicit ADR; `air.Parse` performs that resolution while reading, and `air.Serialize` always emits the resolved per-frame boxes rather than reconstructing a default/override split.
- Parsing error handling was deliberately split into its own backlog item after the happy-path parser; `air.Parse` now has a full contract for malformed `.air` content — comment lines are ignored, an empty file is an explicit empty result (not an error), and a malformed header/frame line/reader failure, or a group/image index more negative than the `-1` blank-frame sentinel, returns a descriptive, line-numbered error rather than panicking.
- Real-world `.air` files widely use `-1` (most commonly `-1,-1`) on a frame line's group/image field as an engine-recognized "no sprite shown" convention, not a data error; `air.Frame.IsBlank()` names that state directly on the pure-data model (`Group < 0 || Image < 0`) rather than adding a separate boolean field, so `air.Parse` accepts it, and `air.SpriteResolver.Resolve` short-circuits to a zero `Sprite`/`nil` error for it instead of attempting (and failing) a sprite-index lookup — kept distinct from a genuinely missing `(Group, Image)` reference, which still errors. See an explicit ADR.
- `air.Serialize` always writes fresh text: a semantic round trip through `air.Parse`, not byte-exact preservation of an original file's formatting or comments. Format-preserving round trips instead go through a separate write-path type (`air.Document`) rather than extending the pure-data model or `Parse`/`Serialize` — comment/ordering preservation stays out of the read-only `Animation`/`Frame` vocabulary, per an explicit ADR. `Document` currently only guarantees this for *unmodified* content; it does not yet regenerate output around edits while preserving unrelated comments.
- `air` now depends on `sff` — the first real cross-package dependency in the codebase — for `SpriteResolver`, which resolves a `Frame`'s `(Group, Image)` reference against a `[]sff.SpriteGroup`. The dependency runs one way only (`sff` still depends on nothing), matching CLAUDE.md's architecture diagram, which already documented `.air` as depending on `.sff`. A missing sprite reference is a returned error, never a silently zero-value `Sprite`, per an explicit ADR.
- Version-specific binary parsers/decoders (e.g. `sff.ParseV1`, `sff.ParseV2`, `sff.DecodePCX`, `sff.DecodeV2Sprite`) return a separate, version/encoding-specific low-level type (`V1SpriteTable`/`V1SpriteEntry`, `V2SpriteTable`/`V2SpriteEntry`/`V2PaletteEntry`, `PCXImage`, `V2Image`) rather than populating the shared read-path model directly, when the shared model can't yet hold everything the parser produces (file offsets) or needs (decoded pixel dimensions, palette resolution, per-pixel byte width for indexed vs. direct-color data) — per an explicit ADR, same rationale as the `air.Document` split.
- Their write-path counterparts (`sff.SerializeV1`, `sff.EncodePCX`, `sff.SerializeV2`, `sff.EncodeV2Sprite`) mirror this with their own write-only input types (`V1WriteSprite`, `V2WriteSprite`/`V2WritePalette`), and — unlike `air.Document` — target a semantic round trip (serialize → re-parse → re-decode → compare), not a byte-exact one: `.sff` is binary with no diff-friendliness benefit to preserving an original file's exact layout, per an explicit ADR. `sff.SerializeV2` always writes into the file's single literal data section and `sff.EncodeV2Sprite` only handles the raw/PNG format scope `sff.DecodeV2Sprite` originally decoded, not its later RLE8/LZ5 decode-side additions, per the same ADR pattern.
- `sff.ResolvePixels`/`Palette` extend the "separate opt-in type, not a field on the pure-data read-path model" pattern one step further: turning a decoded index buffer into actual colors needs a resolved 256-entry `Palette`, never added to `PCXImage`/`V2Image`/`Sprite`. Getting that `Palette` is version-specific (v1's palette is embedded RGB bytes *after* a sprite's own pixel data — empirically confirmed against the real fixtures that `V1SpriteEntry.Length` does not include it, ruling out reading it as a suffix of `DecodePCX`'s own input; v2's is already-RGBA bank data, independently linkable like a sprite's own pixel data), but the final index-to-color resolution and its `AlphaRule` (forced-transparent-at-index-0 vs. literal alpha) are shared across both versions. See an explicit ADR.
