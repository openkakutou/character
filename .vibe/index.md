# character — Codebase index

## Modules
- [`modules/root.md`](modules/root.md) — entry point; assembles `air`/`def`/`cns` data, plus the external `github.com/openkakutou/sff` module for sprites, into a single `Character` struct, with frame-to-sprite resolution via `ResolveSprite`, a full `.def`-driven load via `Load`, and a filesystem-independent `LoadBytes` for in-memory byte buffers (used by `cmd/wasm`), completing the full read surface across all four MUGEN/Ikemen file formats
- [`modules/wasm.md`](modules/wasm.md) — `cmd/wasm`, the library's WebAssembly entrypoint: build-tag-gated `syscall/js` glue exposing `LoadBytes` and the external `sff` module's `ResolveSpritePixels` (as a batched, stateless `resolveSprites` global) to a browser as JS-callable global functions, verified by a Node.js smoke harness since `syscall/js` code cannot run under the plain Go toolchain
- [`modules/air.md`](modules/air.md) — `.air` animation read and write paths: pure-data model (`Animation`, `Frame` with `IsBlank()`, `ClsnBox`), a `Parse` function reading `.air` text into it (accepting any negative group/image value as the blank-frame sentinel), a `Serialize` function writing it back out, a `Document`/`ParseDocument` pair for byte-exact, comment-preserving round trips of unmodified files, and a `SpriteResolver` resolving each `Frame`'s sprite reference against sprites loaded via the external `github.com/openkakutou/sff` module — recognizing a blank frame directly instead of attempting a lookup
- [`modules/def.md`](modules/def.md) — `.def` character definition read and write paths: pure-data `CharacterInfo` (name, author, and referenced file paths per `.def` section), a `Parse` function reading `[Info]`/`[Files]` text into it while skipping unrecognized sections/keys, a `Serialize` function writing it back out, and a `Document`/`ParseDocument` pair for byte-exact, comment-preserving round trips of unmodified files — completing the `def` read+write cycle; wired into `Character` via the root package's `Load`
- [`modules/cns.md`](modules/cns.md) — `.cns` combat logic read and write paths: pure-data model `StateDef` (a Statedef header plus its `Controller`s) and `Controller` (a state controller stored as unevaluated `Triggers`/`Parameters`), plus `StateType`/`MoveType`/`PhysicsType` enums, a `Parse` function reading `[Statedef N]`/`[State ...]` text into them, a `Serialize` function writing it back out, and a `Document`/`ParseDocument` pair for byte-exact, comment-preserving round trips of unmodified files — completing the `cns` read+write cycle; wired into `Character` via the root package's `Load`; `Parse` now also tolerates four real-world file patterns found by corpus scans (a `[State ...]` header with no state number, a numeric header field holding a MUGEN trigger expression, a `[Statedef ...]`/`[State ...]` header missing its closing `]`, and a non-header content line inside a block that isn't a valid `key=value` pair), the second surfaced on `StateDef` via a `HeaderExprs` escape-hatch field

## Observed patterns
- Root package (`character`) is a thin assembly layer over format-specific sub-packages (`def/`, `air/`, `cns/`), plus the external `github.com/openkakutou/sff` module for sprites — it composes `air.Animation`/`sff.SpriteGroup`/`cns.StateDef` into `Character`, delegates frame-to-sprite resolution to `air.NewSpriteResolver` rather than reimplementing it, and loads a full `Character` directly from a `.def` file path (`Load`) by delegating to `def.Parse`/`air.Parse`/`sff.Load`/`cns.Parse` in turn rather than reimplementing any of their file-reading logic — completing the roadmap's full read surface across all four formats; `air/` now has a data model, a read-path parser, a write-path serializer, a format-preserving `Document` type, and a `SpriteResolver` resolving frame references against loaded sprites; `def/` now has a complete read+write cycle too (`CharacterInfo`, `Parse`, `Serialize`, `Document`/`ParseDocument`), matching the "data model before parser" order `air`/`sff` followed, and is now wired into `Character`; `cns/` now also has a complete read+write cycle (`StateDef`, `Controller`, `StateType`/`MoveType`/`PhysicsType`, `Parse`, `Serialize`, `Document`/`ParseDocument`), matching the same "data model before parser" order `air`/`def` followed, and is now wired into `Character` too, via `Load`'s `ConstantsFile` reference — real-world `.cns` files spot-checked against a local corpus during that wiring showed `cns.Parse` rejecting a majority of them (state headers with non-numeric/missing numbers, header fields holding MUGEN expression syntax instead of literal integers), a pre-existing gap in `cns.Parse` itself, out of that wiring item's scope — closed by a later item: a `[State ...]` header's content is now unconstrained (no state number required, since `Parse` never stored it anyway) and a numeric header field that isn't a literal integer is stored verbatim in a new `StateDef.HeaderExprs` field rather than erroring, mirroring `Controller`'s own unevaluated-data philosophy one layer up. See two explicit ADRs. Sprite parsing itself was extracted out of this repo into the external `sff` module (item 035), so other OpenKakutou repos (`stage`, `lifebar`) needing sprite parsing can depend on it without depending on this whole module.
- `cns.Controller` stores its trigger conditions and parameters as untyped, unevaluated data (`[]string`/`map[string]string`) rather than controller-type-specific fields — the same "read-path model can't hold everything yet" reasoning `air`/`sff`'s low-level types followed, but here the driver is scope (no expression engine exists yet), not a format-shape mismatch. See an explicit ADR.
- `sff.Load` (and, transitively, `character.Load`) resolves the "meaning is version-defined" ambiguity `Sprite.Palette`'s doc comment left open: for v1, which only records a per-sprite "reuses previous sprite's palette" boolean on disk, it derives a numeric value via a running counter (incremented on every non-shared sprite, inherited by sharing sprites) rather than leaving every v1 sprite at a constant placeholder; for v2, the table already has a real numeric palette bank index, so it's used as-is with no derivation needed — this behavior now lives in the external `sff` module, not this repo's own code. Referenced `.def` file paths (`.air`/`.sff`) are resolved against the `.def` file's own directory, not the process's working directory. See an explicit ADR.
- `def.Parse` follows the same "read-path model can't hold everything, so drop what it can't represent" pattern as `air.Document`'s split (per an explicit ADR): unrecognized `.def` sections are skipped rather than erroring or being smuggled onto `CharacterInfo`; `def.Document`/`def.ParseDocument` are that write path's format-preserving counterpart, mirroring `air.Document` exactly — including the same limitation that it only guarantees byte-exact preservation for *unmodified* content, not regeneration around edits.
- `cns.Parse` extends `def.Parse`'s "skip unrecognized sections" tolerance one step further: a bracket line that isn't a `[Statedef N]`/`[State N]` header is skipped without validation (same as `def.Parse`'s unknown `.def` sections), but a bracket line that *looks like* an attempted Statedef/State header yet fails to parse (missing/non-numeric state number) still returns a line-numbered error rather than being silently skipped — distinguishing "genuinely unrelated content" from "a typo in the two header shapes this parser is responsible for". See an explicit ADR.
- `cns.Serialize`/`cns.Document` mirror the `def` write path exactly: `Serialize` always writes fresh text (a semantic round trip through `Parse`, not byte-exact preservation), while `cns.Document`/`ParseDocument` is the separate format-preserving type guaranteeing a byte-exact round trip for *unmodified* content only, per the same explicit ADR `air`/`def` already followed. Because `Controller.Parameters` is an unordered map and `Triggers` never records which `trigger1`/`trigger2`/`triggerall` key produced it, `Serialize` renumbers `Triggers` sequentially and sorts `Parameters` by key for deterministic output rather than attempting to reconstruct the original key names — a distinction `cns.Parse` already discards on read, not a new loss introduced by the write path.
- Tests are co-located with source as `*_test.go`, one behavior per test function, named `Test<Type>_<Condition>_<Expectation>`.
- Read-path data types (e.g. `air.Animation`/`air.Frame`) store already-resolved values (e.g. per-frame collision boxes) rather than the file format's own authoring shortcuts (e.g. default/override) — parsing concerns stay out of the pure-data model, per an explicit ADR; `air.Parse` performs that resolution while reading, and `air.Serialize` always emits the resolved per-frame boxes rather than reconstructing a default/override split.
- Parsing error handling was deliberately split into its own backlog item after the happy-path parser; `air.Parse` now has a full contract for malformed `.air` content — comment lines are ignored, an empty file is an explicit empty result (not an error), and a malformed header/frame line or reader failure returns a descriptive, line-numbered error rather than panicking.
- Real-world `.air` files use any negative value (not just `-1` — a corpus example uses `-1,0`/`-1,-1`/`-1,-2`/`-1,-3`/... within one action) on a frame line's group/image field as an engine-recognized "no sprite shown" convention, not a data error; `air.Frame.IsBlank()` names that state directly on the pure-data model (`Group < 0 || Image < 0`) rather than adding a separate boolean field, so `air.Parse` accepts any negative value on either field with no lower bound, and `air.SpriteResolver.Resolve` short-circuits to a zero `Sprite`/`nil` error for it instead of attempting (and failing) a sprite-index lookup — kept distinct from a genuinely missing `(Group, Image)` reference, which still errors. `air.Parse` initially only accepted the exact `-1,-1` pair, tightened later to any negative value once a real character file (Bardock) surfaced the narrower rule as a false rejection. See two explicit ADRs (the second supersedes the first).
- `air.Serialize` always writes fresh text: a semantic round trip through `air.Parse`, not byte-exact preservation of an original file's formatting or comments. Format-preserving round trips instead go through a separate write-path type (`air.Document`) rather than extending the pure-data model or `Parse`/`Serialize` — comment/ordering preservation stays out of the read-only `Animation`/`Frame` vocabulary, per an explicit ADR. `Document` currently only guarantees this for *unmodified* content; it does not yet regenerate output around edits while preserving unrelated comments.
- `air` depends on the external `github.com/openkakutou/sff` module — the first real cross-package(-boundary) dependency in the codebase — for `SpriteResolver`, which resolves a `Frame`'s `(Group, Image)` reference against a `[]sff.SpriteGroup`. The dependency runs one way only, matching CLAUDE.md's architecture diagram, which already documented `.air` as depending on `.sff`. A missing sprite reference is a returned error, never a silently zero-value `Sprite`, per an explicit ADR.
- Every read-path type reachable from `Character` (`air.Animation`/`Frame`/`ClsnBox`, `sff.Sprite`/`SpriteGroup`, `cns.StateDef`/`Controller`) now carries explicit `json:"..."` tags, pinning a deliberate wire contract rather than riding on Go's default field-name reflection — added for `character.LoadBytes`/`cmd/wasm`'s JSON/JS boundary, but the tags live on the shared read-path types themselves, not a separate DTO layer. `LoadBytes` additionally normalizes every reachable nil slice/map to its non-nil empty equivalent before returning, a guarantee specific to that function (ordinary `Parse`/`Load` callers still see idiomatic Go nil slices). See an explicit ADR.
- `cmd/wasm` is the first package in the module gated by a Go build constraint (`//go:build js && wasm`) rather than by directory convention alone — this keeps a normal host `go build ./...`/`go test ./...` from ever touching `syscall/js`-only code, which only compiles for `GOOS=js`. Its own correctness is instead verified by a Node.js script (`smoke.mjs`) that loads the built module the way a real browser would, since `syscall/js` code cannot run under the plain Go toolchain; `smoke.mjs` keeps its own small fixture set under `cmd/wasm/testdata/` since item 035 moved the `sff` package's own testdata out of this repo.
- `cmd/wasm`'s exposed functions batch rather than go stateful when a single call would be expensive to repeat: `resolveSprites` takes many `(group, image)` requests per call so a `.sff` file's bytes cross the JS/WASM boundary once per batch, not once per sprite, while still re-parsing the file fresh each call rather than keeping a Go-side session alive between calls — see `.vibe/decisions/020-wasm-sprite-pixel-resolution-batched-stateless-contract.md`.
- Sprite (`.sff`) parsing's own internal implementation patterns (version-specific low-level parser/decoder types, semantic vs. byte-exact round-trip strategy, palette resolution, fixture-driven real-file testing) moved with the code itself into the external `github.com/openkakutou/sff` module (item 035) and are no longer tracked here — see that module's own `.vibe/` for its current patterns. The `.vibe/decisions/` ADRs recording *why* they were originally shaped that way remain in this repo as history.
