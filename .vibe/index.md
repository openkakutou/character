# character — Codebase index

## Modules
- [`modules/root.md`](modules/root.md) — entry point; assembles `air`/`def`/`cns` data, plus the external `github.com/openkakutou/sff` module for sprites, into a single `Character` struct, with frame-to-sprite resolution via `ResolveSprite`, a full `.def`-driven load via `Load` (normalizing Windows-style backslash separators in referenced file paths before resolving them, item 049, falling back to a case-insensitive match against on-disk directory entries when a referenced file's exact-case name doesn't exist, item 050, and now rejecting a `.def` with no `[Files]` section at all — e.g. an Ikemen GO storyboard/ending screen `.def` — with a clear diagnostic instead of an opaque "is a directory" filesystem error, item 051), and a filesystem-independent `LoadBytes` for in-memory byte buffers (used by `cmd/wasm`), completing the full read surface across all four MUGEN/Ikemen file formats. Both `Load` and `LoadBytes` now thread every `def.CharacterInfo` field (author, referenced file paths) onto `Character`, not just `Name`, item 038. `SerializeDef`/`SerializeAir`/`SerializeCns`/`SerializeCmd`/`SerializeZss` (item 039) complete the write side: byte-exact to the original when a normalized in-memory model matches what parsing it produces, freshly serialized otherwise
- [`modules/wasm.md`](modules/wasm.md) — `cmd/wasm`, the library's WebAssembly entrypoint: build-tag-gated `syscall/js` glue exposing `LoadBytes` and the external `sff` module's `ResolveSpritePixels` (as a batched, stateless `resolveSprites` global) to a browser as JS-callable global functions, plus five `saveDef`/`saveAir`/`saveCns`/`saveCmd`/`saveZss` globals over the root package's new `SerializeX` functions (item 039), verified by a Node.js smoke harness since `syscall/js` code cannot run under the plain Go toolchain
- [`modules/air.md`](modules/air.md) — `.air` animation read and write paths: pure-data model (`Animation`, `Frame` with `IsBlank()`, `ClsnBox`), a `Parse` function reading `.air` text into it (accepting any negative group/image value as the blank-frame sentinel, recognizing/skipping Ikemen GO's Interpolate directive lines (item 045), tolerating optional whitespace before a Clsn box line's `[index]` bracket (item 047), tolerating the misspelled Clsn declaration keyword `Clsn1deault`/`Clsn2deault` as `Clsn1Default`/`Clsn2Default` (item 052), treating a whole line starting with `:` as a comment, the same as `;` (item 054), and now also skipping a bracket line that isn't an attempted `[Begin Action N]` header — e.g. a combat-logic block embedded mid-file (item 055) — rather than erroring, while a genuinely malformed `[Begin Action N]` attempt still errors), a `Serialize` function writing it back out, a `Document`/`ParseDocument` pair for byte-exact, comment-preserving round trips of unmodified files, and a `SpriteResolver` resolving each `Frame`'s sprite reference against sprites loaded via the external `github.com/openkakutou/sff` module — recognizing a blank frame directly instead of attempting a lookup
- [`modules/def.md`](modules/def.md) — `.def` character definition read and write paths: pure-data `CharacterInfo` (name, author, and referenced file paths per `.def` section), a `Parse` function reading `[Info]`/`[Files]` text into it while skipping unrecognized sections/keys (and now tolerating a non-`key=value` content line inside a known section, item 044), a `Serialize` function writing it back out, and a `Document`/`ParseDocument` pair for byte-exact, comment-preserving round trips of unmodified files — completing the `def` read+write cycle; wired into `Character` via the root package's `Load`
- [`modules/cns.md`](modules/cns.md) — `.cns` combat logic read and write paths: pure-data model `StateDef` (a Statedef header plus its `Controller`s) and `Controller` (a state controller stored as unevaluated `Triggers`/`Parameters`), plus `StateType`/`MoveType`/`PhysicsType` enums, a `Parse` function reading `[Statedef N]`/`[State ...]` text into them, a `Serialize` function writing it back out, and a `Document`/`ParseDocument` pair for byte-exact, comment-preserving round trips of unmodified files — completing the `cns` read+write cycle; wired into `Character` via the root package's `Load`; `Parse` now also tolerates five real-world file patterns found by corpus scans (a `[State ...]` header with no state number, a numeric or boolean header field holding a MUGEN trigger expression, a `[Statedef ...]`/`[State ...]` header missing its closing `]`, and a non-header content line inside a block that isn't a valid `key=value` pair), the numeric/boolean case surfaced on `StateDef` via a shared `HeaderExprs` escape-hatch field
- [`modules/cmd.md`](modules/cmd.md) — `.cmd` input command read and write paths: pure-data model `CommandFile`/`CommandDefaults`/`Command`, a `Parse` function reading `[Remap]`/`[Defaults]`/`[Command]` text into them while delegating the shared `[Statedef -1]`/`[State ...]` block directly to `cns.Parse` (synthesizing an implicit `[Statedef -1]` header first when a real-world file omits it), a `Serialize` function writing it back out (delegating that same block to `cns.Serialize`), and a `Document`/`ParseDocument` pair for byte-exact, comment-preserving round trips of unmodified files; validated against a 520-file real-character corpus (99.8% success at the time, the one remaining failure a `cns.Parse` gap since fixed as item 053); not yet wired into `Character`
- [`modules/zss.md`](modules/zss.md) — `.zss` Ikemen GO Lua-like state script read and write paths (an alternative to `.cns`, item 037): pure-data model `Script`/`Block`/`BlockKind`, a `Parse` function splitting `.zss` text into `[Statedef ...]`/`[Function ...]` blocks (parsing each header into typed fields, tolerating a Statedef header wrapped across several physical lines) while keeping each block's own Lua-like script body as raw, unevaluated text, a `Serialize` function writing it back out, and a `Document`/`ParseDocument` pair for byte-exact round trips of unmodified files; validated against a real Ikemen GO character's `.zss` files (390 blocks across 7 files, all round-tripping identically); shares no syntax with `cns`, unlike `cmd`; not yet wired into `Character`

## Observed patterns
- Root package (`character`) is a thin assembly layer over format-specific sub-packages (`def/`, `air/`, `cns/`), plus the external `github.com/openkakutou/sff` module for sprites — it composes `air.Animation`/`sff.SpriteGroup`/`cns.StateDef` into `Character`, delegates frame-to-sprite resolution to `air.NewSpriteResolver` rather than reimplementing it, and loads a full `Character` directly from a `.def` file path (`Load`) by delegating to `def.Parse`/`air.Parse`/`sff.Load`/`cns.Parse` in turn rather than reimplementing any of their file-reading logic — completing the roadmap's full read surface across all four formats; `air/` now has a data model, a read-path parser, a write-path serializer, a format-preserving `Document` type, and a `SpriteResolver` resolving frame references against loaded sprites; `def/` now has a complete read+write cycle too (`CharacterInfo`, `Parse`, `Serialize`, `Document`/`ParseDocument`), matching the "data model before parser" order `air`/`sff` followed, and is now wired into `Character`; `cns/` now also has a complete read+write cycle (`StateDef`, `Controller`, `StateType`/`MoveType`/`PhysicsType`, `Parse`, `Serialize`, `Document`/`ParseDocument`), matching the same "data model before parser" order `air`/`def` followed, and is now wired into `Character` too, via `Load`'s `ConstantsFile` reference — real-world `.cns` files spot-checked against a local corpus during that wiring showed `cns.Parse` rejecting a majority of them (state headers with non-numeric/missing numbers, header fields holding MUGEN expression syntax instead of literal integers), a pre-existing gap in `cns.Parse` itself, out of that wiring item's scope — closed by a later item: a `[State ...]` header's content is now unconstrained (no state number required, since `Parse` never stored it anyway) and a numeric header field that isn't a literal integer is stored verbatim in a new `StateDef.HeaderExprs` field rather than erroring, mirroring `Controller`'s own unevaluated-data philosophy one layer up. See two explicit ADRs. Sprite parsing itself was extracted out of this repo into the external `sff` module (item 035), so other OpenKakutou repos (`stage`, `lifebar`) needing sprite parsing can depend on it without depending on this whole module.
- `cns.Controller` stores its trigger conditions and parameters as untyped, unevaluated data (`[]string`/`map[string]string`) rather than controller-type-specific fields — the same "read-path model can't hold everything yet" reasoning `air`/`sff`'s low-level types followed, but here the driver is scope (no expression engine exists yet), not a format-shape mismatch. See an explicit ADR.
- `sff.Load` (and, transitively, `character.Load`) resolves the "meaning is version-defined" ambiguity `Sprite.Palette`'s doc comment left open: for v1, which only records a per-sprite "reuses previous sprite's palette" boolean on disk, it derives a numeric value via a running counter (incremented on every non-shared sprite, inherited by sharing sprites) rather than leaving every v1 sprite at a constant placeholder; for v2, the table already has a real numeric palette bank index, so it's used as-is with no derivation needed — this behavior now lives in the external `sff` module, not this repo's own code. Referenced `.def` file paths (`.air`/`.sff`) are resolved against the `.def` file's own directory, not the process's working directory. See an explicit ADR.
- `def.Parse` follows the same "read-path model can't hold everything, so drop what it can't represent" pattern as `air.Document`'s split (per an explicit ADR): unrecognized `.def` sections are skipped rather than erroring or being smuggled onto `CharacterInfo`; `def.Document`/`def.ParseDocument` are that write path's format-preserving counterpart, mirroring `air.Document` exactly — including the same limitation that it only guarantees byte-exact preservation for *unmodified* content, not regeneration around edits. `def.Parse` now also tolerates a non-header content line inside a known section that isn't a valid `key=value` pair (a truncated leftover key, a decorative separator), ignoring it instead of erroring — the same real-world-compatibility tolerance `cns.Parse` already applies (item 043), applied here as item 044's fix.
- `cns.Parse` extends `def.Parse`'s "skip unrecognized sections" tolerance one step further: a bracket line that isn't a `[Statedef N]`/`[State N]` header is skipped without validation (same as `def.Parse`'s unknown `.def` sections), but a bracket line that *looks like* an attempted Statedef/State header yet fails to parse (missing/non-numeric state number) still returns a line-numbered error rather than being silently skipped — distinguishing "genuinely unrelated content" from "a typo in the two header shapes this parser is responsible for". See an explicit ADR. That distinction now also governs the *unclosed*-bracket case symmetrically: an unclosed line that isn't recognizable as either header attempt (e.g. a decorative section-banner line, found in King of Fighters' "Shun Ei") is skipped without erroring too, the same as a closed one always was, rather than hitting a blanket "malformed section header" error (item 053) — which also surfaced a latent gap in the attempt-detection regexes themselves (`cns`'s own and `cmd`'s mirrored copy for its three headers): a bare header keyword with nothing else on the line (e.g. `[Statedef`/`[Command` with no trailing space or bracket) wasn't recognized as an attempt at all, so it's now matched at end-of-line too, keeping a genuine bare-keyword typo an error instead of being swallowed by the new tolerance.
- `cns.Serialize`/`cns.Document` mirror the `def` write path exactly: `Serialize` always writes fresh text (a semantic round trip through `Parse`, not byte-exact preservation), while `cns.Document`/`ParseDocument` is the separate format-preserving type guaranteeing a byte-exact round trip for *unmodified* content only, per the same explicit ADR `air`/`def` already followed. Because `Controller.Parameters` is an unordered map and `Triggers` never records which `trigger1`/`trigger2`/`triggerall` key produced it, `Serialize` renumbers `Triggers` sequentially and sorts `Parameters` by key for deterministic output rather than attempting to reconstruct the original key names — a distinction `cns.Parse` already discards on read, not a new loss introduced by the write path.
- `cns.Parse`'s numeric-header-field expression escape hatch (ADR 023) has been extended to the five boolean header fields (`ctrl`, `facep2`, `hitdefpersist`, `movehitpersist`, `hitcountpersist`): real files use MUGEN trigger expressions on these just as often as on the numeric ones (e.g. the BlazBlue "Mai" and JoJo's Bizarre Adventure "Avdol" characters), so a value that fails `strconv.ParseBool` is now stored verbatim in the same `HeaderExprs` map instead of erroring, and `cns.Serialize` writes it back out verbatim the same way it already does for numeric fields (backlog item 046).
- Tests are co-located with source as `*_test.go`, one behavior per test function, named `Test<Type>_<Condition>_<Expectation>`.
- Read-path data types (e.g. `air.Animation`/`air.Frame`) store already-resolved values (e.g. per-frame collision boxes) rather than the file format's own authoring shortcuts (e.g. default/override) — parsing concerns stay out of the pure-data model, per an explicit ADR; `air.Parse` performs that resolution while reading, and `air.Serialize` always emits the resolved per-frame boxes rather than reconstructing a default/override split.
- Parsing error handling was deliberately split into its own backlog item after the happy-path parser; `air.Parse` now has a full contract for malformed `.air` content — comment lines are ignored, an empty file is an explicit empty result (not an error), and a malformed header/frame line or reader failure returns a descriptive, line-numbered error rather than panicking.
- Real-world `.air` files use any negative value (not just `-1` — a corpus example uses `-1,0`/`-1,-1`/`-1,-2`/`-1,-3`/... within one action) on a frame line's group/image field as an engine-recognized "no sprite shown" convention, not a data error; `air.Frame.IsBlank()` names that state directly on the pure-data model (`Group < 0 || Image < 0`) rather than adding a separate boolean field, so `air.Parse` accepts any negative value on either field with no lower bound, and `air.SpriteResolver.Resolve` short-circuits to a zero `Sprite`/`nil` error for it instead of attempting (and failing) a sprite-index lookup — kept distinct from a genuinely missing `(Group, Image)` reference, which still errors. `air.Parse` initially only accepted the exact `-1,-1` pair, tightened later to any negative value once a real character file (Bardock) surfaced the narrower rule as a false rejection. See two explicit ADRs (the second supersedes the first).
- `air.Parse` now also tolerates Ikemen GO's `Interpolate Offset`/`Interpolate Blend`/`Interpolate Scale`/`Interpolate Angle` directive lines (a real-world `.air` construct that smoothly transitions a property across an animation, previously misread as a malformed frame line) — recognized by exact keyword match and skipped, mirroring how `Loopstart` is already recognized-but-not-modeled; the directive's own data isn't represented on `Animation`/`Frame` yet (item 045). Verifying this fix against a second real fixture (Donovan) surfaced an unrelated gap — a misspelled `Clsn2Default` keyword — filed separately as item 052 rather than fixed here, since it's a different root cause. `air.Parse`'s Clsn box line pattern now also tolerates optional whitespace between the `Clsn1`/`Clsn2` keyword and its `[index]` bracket (e.g. `Clsn2 [0] = ...`), a real-world authoring style found in several real characters (King of Fighters "Mai (98)" among them, item 047) that real MUGEN/Ikemen engines tolerate; a genuinely malformed Clsn box line (wrong coordinate count, non-numeric coordinate) still returns the same descriptive, line-numbered error. Runtime-verifying that fix against the same "Mai (98)" fixture surfaced a further, unrelated parse failure later in the same file (a `:`-prefixed comment line instead of the standard `;`) — filed separately as item 054 rather than fixed here, same precedent as item 052, and fixed there: `air.Parse` now treats a whole line starting with `:` as a comment too, resolving the "Mai (98)" fixture's remaining failure. Ikemen GO's own reference source (`anim.go`'s `ReadAnimFrame`) confirms `:` isn't a literal comment marker there either, but a line that doesn't start with a digit or `-` is never treated as an attempted frame line — it's silently ignored with no error — so this narrow, `;`-mirroring fix produces the same observable outcome as the real engine for this specific real-world quirk, without loosening the stricter "attempted-but-malformed frame line" error path this repo already enforces for other unrecognized content (e.g. `abc,0,...`). `air.Parse`'s frame-line numeric fields (Group, Image, X, Y, Time) now parse only their leading integer rather than requiring the whole comma-separated field to be strictly numeric — tolerating non-numeric trailing content (e.g. `143 0`) and a genuinely blank field (defaulting to 0, which happens when a real file is missing a comma and shifts a later field's content into an earlier one), confirmed against Ikemen GO's own reference `Atoi` (`src/common.go`), which scans a leading digit run and stops at the first non-digit; a field with no usable leading digits at all still returns the existing descriptive, line-numbered error (item 048). Found via corpus scan: the identical broken frame line was copy-pasted across 14 unrelated real characters (Dragon Ball "Goku", Guilty Gear "Axl"/"Baiken" among them). `air.Parse`'s Clsn declaration header now also tolerates the specific misspelling `Clsn1deault`/`Clsn2deault` (missing the "f" in "Default") alongside the correct spelling, mapping it to the same `Clsn1Default`/`Clsn2Default` meaning rather than falling through to frame-line parsing and erroring — a real-world authoring typo found in a real character (Darkstalkers "Donovan", item 052), the same narrow-tolerance precedent `def.Parse`/`cns.Parse` already follow for other specific real-world authoring mistakes rather than open-ended fuzzy matching. Runtime-verifying backlog item 050's fix against a real fixture (One Piece "Luffy") surfaced a further, unrelated gap: the file's `.air` carries an embedded `[Statedef 1060]` combat-logic block (with its own `[State ...]` sub-blocks) partway through, which `air.Parse` treated as a malformed action header — filed separately as item 055 and fixed there, following the same "distinguish a genuine attempt at this package's own header from unrelated content" strategy `cns.Parse`'s `statedefAttemptPattern`/`stateAttemptPattern` already established: a bracket line is only an error if it looks like an attempt at `[Begin Action N]` (starts with the `begin` keyword); any other bracket line, and the content lines following it, are skipped as belonging to a section outside `air.Parse`'s scope.
- `air.Serialize` always writes fresh text: a semantic round trip through `air.Parse`, not byte-exact preservation of an original file's formatting or comments. Format-preserving round trips instead go through a separate write-path type (`air.Document`) rather than extending the pure-data model or `Parse`/`Serialize` — comment/ordering preservation stays out of the read-only `Animation`/`Frame` vocabulary, per an explicit ADR. `Document` currently only guarantees this for *unmodified* content; it does not yet regenerate output around edits while preserving unrelated comments.
- `air` depends on the external `github.com/openkakutou/sff` module — the first real cross-package(-boundary) dependency in the codebase — for `SpriteResolver`, which resolves a `Frame`'s `(Group, Image)` reference against a `[]sff.SpriteGroup`. The dependency runs one way only, matching CLAUDE.md's architecture diagram, which already documented `.air` as depending on `.sff`. A missing sprite reference is a returned error, never a silently zero-value `Sprite`, per an explicit ADR.
- Every read-path type reachable from `Character` (`air.Animation`/`Frame`/`ClsnBox`, `sff.Sprite`/`SpriteGroup`, `cns.StateDef`/`Controller`) now carries explicit `json:"..."` tags, pinning a deliberate wire contract rather than riding on Go's default field-name reflection — added for `character.LoadBytes`/`cmd/wasm`'s JSON/JS boundary, but the tags live on the shared read-path types themselves, not a separate DTO layer. `LoadBytes` additionally normalizes every reachable nil slice/map to its non-nil empty equivalent before returning, a guarantee specific to that function (ordinary `Parse`/`Load` callers still see idiomatic Go nil slices). See an explicit ADR.
- `cmd/wasm` is the first package in the module gated by a Go build constraint (`//go:build js && wasm`) rather than by directory convention alone — this keeps a normal host `go build ./...`/`go test ./...` from ever touching `syscall/js`-only code, which only compiles for `GOOS=js`. Its own correctness is instead verified by a Node.js script (`smoke.mjs`) that loads the built module the way a real browser would, since `syscall/js` code cannot run under the plain Go toolchain; `smoke.mjs` keeps its own small fixture set under `cmd/wasm/testdata/` since item 035 moved the `sff` package's own testdata out of this repo.
- `cmd/wasm`'s exposed functions batch rather than go stateful when a single call would be expensive to repeat: `resolveSprites` takes many `(group, image)` requests per call so a `.sff` file's bytes cross the JS/WASM boundary once per batch, not once per sprite, while still re-parsing the file fresh each call rather than keeping a Go-side session alive between calls — see `.vibe/decisions/020-wasm-sprite-pixel-resolution-batched-stateless-contract.md`.
- Sprite (`.sff`) parsing's own internal implementation patterns (version-specific low-level parser/decoder types, semantic vs. byte-exact round-trip strategy, palette resolution, fixture-driven real-file testing) moved with the code itself into the external `github.com/openkakutou/sff` module (item 035) and are no longer tracked here — see that module's own `.vibe/` for its current patterns. The `.vibe/decisions/` ADRs recording *why* they were originally shaped that way remain in this repo as history.
- `cmd/` (a `.cmd` input-command package, not to be confused with the pre-existing `cmd/wasm` WASM binary directory one level down — a naming coincidence already anticipated in this repo's own CLAUDE.md architecture diagram) reuses `cns.Parse`/`cns.Serialize` directly for the `.cmd`-format's `[Statedef -1]`/`[State ...]` block rather than reimplementing it, since the two formats share that syntax byte-for-byte — the first instance of one format-specific package depending on another (as opposed to the root package assembling several, or a format package depending on the external `sff` module). The command-to-state link needs no dedicated field: it already flows through `cns.Controller.Triggers`'s existing unevaluated strings (e.g. `command = "holdback"`). See two explicit ADRs (025, 026 — the second covers a real-world quirk: some `.cmd` files omit `[Statedef -1]` entirely, which `cmd.Parse` compensates for before delegating).
- `zss/` takes the "unevaluated data" philosophy one step further than `cns.Controller`/`cmd.Command`: instead of storing individual fields as raw strings, an entire block's script body (the Lua-like statements between one `[Statedef ...]`/`[Function ...]` header and the next) is kept as one opaque raw-text field, since `.zss` is a full scripting language this repo has no execution engine for — only the header itself (state number / function name+params+ret, plus a Statedef's semicolon-separated key:value fields) is parsed into structured data. Unlike `cmd`, `zss` shares no syntax with `cns` and depends on nothing else in this repo. A real corpus scan surfaced one real-world quirk: a Statedef header's parameters sometimes wrap across several physical lines before the closing `]`, which `Parse` recovers by joining continuation lines into one logical header before matching it. See an explicit ADR (027).
