# .zss scripts are wired into Character following Ikemen GO's file selection
**Context:** Backlog item 060. The `zss` package parses and round-trips `.zss`, but `Character` did not load or expose it, and `def.Parse` dropped `stcommon`.
**Decision:** `Character.Scripts` (`[]ScriptFile{File, Script, Error}`, JSON `scripts`) holds every `.zss` referenced by `st`, `stN` and `stcommon`, in Ikemen GO's load order (`st`, `stN` by number, then `stcommon`). One resolver holds the selection rule (extension `.zss`, case-insensitive; when a referenced file is not found, `<name>.zss` is tried) and is fed by a disk opener (`Load`) or a lookup in the new trailing `LoadBytes` argument `zssFiles map[string][]byte`, keyed by the `.def` entry text (separators and case folded); the WASM `load` takes it as an optional 7th argument (a JS object). A missing or malformed `.zss` is non-fatal: the entry carries `Error`, naming the file and step (decision 031). A `.zss` `stcommon` not found in the character folder is reported the same way; a non-`.zss` `stcommon` (usually the engine's `common1.cns`) is skipped silently. `def.CharacterInfo`/`Character` gain `StateCommonFile`; `StateFiles` is now ordered like Ikemen GO (`st` first, then by number), like `Palettes` already is. An empty `cns` entry is no longer a load error (empty `StateDefs`).
**Reason:** Matches Ikemen GO so a real character loads here the way it loads in the engine; one resolver keeps disk and byte loading from drifting; per-file inline errors follow 030/031.
**Rejected alternatives:** Two separate selection loops in `Load` and `LoadBytes` (the rule would drift); replacing `StateFiles` with a table carrying path and content (breaks the JSON contract and every consumer); making a bad `.zss` fatal (inconsistent with 031).
**Compatibility:** Ikemen GO (source `ikemen-engine/Ikemen-GO@063a060`, `src/compiler.go` `stateCompile` and the `[Files]` reading, `src/char.go` constants loading under `if len(cns) > 0`; wiki page "ZSS"): `.zss` comes from `st`/`stN`/`stcommon`, never `cns`; chosen by extension; `<name>.zss` fallback; `.cns` and `.zss` may be mixed. Divergences: Ikemen's extension check is an unanchored regex (`.zssx` would match), here only an exact `.zss` extension counts; Ikemen also searches `stcommon` in the motif and `data/` folders, which a character library cannot see, hence the report. MUGEN 1.0/1.1 has no `.zss`; its characters are unaffected (no `.zss` entry → empty `Scripts`). No community `.zss` character was available; validation used Ikemen GO's own distributed scripts (`data/` of `ikemen-engine/Ikemen-GO@develop`, downloaded to a scratch folder, not committed; these are engine common/system scripts, not a community character): 10 files loaded through `Load` (`st`..`st8` plus the `stcommon = common1.cns` fallback to `common1.cns.zss`), 83 blocks parsed in total, and the 5 that parse (`action`, `functions`, `training`, `score`, `common1.cns`) re-serialize byte-exact; the other 5 (`dizzy`, `guardbreak`, `tag`, `system`, `demo`) are reported as per-file parse errors because the block header parser (ADR 027) rejects `[StateDef const(Name); ...]` and relative `[StateDef +1]` numbers, a known gap left to a follow-up.
