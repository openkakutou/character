# Module: air

**Role:** Read and write paths for MUGEN/Ikemen GO animation (`.air`) files. `animation.go` is the pure-data vocabulary a library consumer (editor, engine) works with, including `Frame.IsBlank()`, which reports whether a frame uses the `.air` "no sprite shown" sentinel — *any* negative value (not just `-1`) on `Group` and/or `Image` — rather than referencing a real sprite. `parser.go` turns `.air` text into that model, covering the format's happy path and hardening against malformed/unusual input — comment lines (`;`, whole-line or trailing) are ignored, an empty file yields an explicit empty result, a frame line's group/image field may hold any negative value as the blank-frame sentinel (no lower bound — see `.vibe/decisions/024-blank-frame-sentinel-accepts-any-negative-value.md`), Ikemen GO's `Interpolate Offset`/`Interpolate Blend`/`Interpolate Scale`/`Interpolate Angle` directive lines are recognized and skipped rather than misread as a malformed frame line, not yet represented on `Animation`/`Frame` (item 045), a Clsn box line tolerates optional whitespace between the `Clsn1`/`Clsn2` keyword and its `[index]` bracket (e.g. `Clsn2 [0] = ...`, a real-world authoring style found in several real characters — item 047) while still rejecting a genuinely malformed box line (wrong coordinate count, non-numeric coordinate) with the same descriptive error, a Clsn declaration header also tolerates the specific misspelling `Clsn1deault`/`Clsn2deault` (missing the "f" in "Default"), mapped to the same `Clsn1Default`/`Clsn2Default` meaning, a real-world authoring typo found in a real character (Darkstalkers "Donovan" — item 052), a frame line's numeric fields (Group, Image, X, Y, Time) parse only their leading integer — tolerating non-numeric trailing content (e.g. `143 0`) and a genuinely blank field (defaulting to 0) rather than requiring the whole field to be a valid integer, mirroring Ikemen GO's own reference number parsing (its `Atoi` in `src/common.go` scans a leading digit run and stops at the first non-digit); a field with no usable leading digits at all still errors — and a malformed action header, a frame line with missing/non-numeric fields, or a reader failure returns a descriptive, line-numbered error rather than panicking or producing incorrect data. `serializer.go` is the inverse: it writes an `[]Animation` back out as valid `.air` text that `Parse` reads back into an equivalent structure, but always as fresh text — Clsn boxes are always emitted per frame (never reconstructed as a `Clsn1Default`/`Clsn2Default`, since `Frame` only stores already-resolved boxes), and a `Loopstart` marker is written only when `LoopStart` is non-zero. `document.go` covers the format-preserving case `Parse`/`Serialize` don't: `ParseDocument` decodes `.air` text the same way `Parse` does while also retaining the original source bytes, and `Document.Serialize` writes those retained bytes back out verbatim — so a round trip on unmodified content reproduces the source file byte-for-byte, comments included. Mutating `Document.Animations` has no effect on `Serialize`'s output (see `.vibe/decisions/003-air-round-trip-via-separate-document-type.md`). `resolve.go` adds `SpriteResolver`, the package's first cross-package integration point: it indexes a `[]sff.SpriteGroup` by `(Group, Image)` once, so `Resolve` can look up any `Frame`'s `sff.Sprite` without rescanning the whole collection, and returns a descriptive error rather than a zero `Sprite` when a frame references a `(Group, Image)` pair absent from the loaded sprites (see `.vibe/decisions/008-air-sprite-resolution-lives-in-air-package.md`); a blank frame (`frame.IsBlank()`) is recognized directly and short-circuits to a zero `Sprite` with a `nil` error instead, since it is a deliberate "no sprite" outcome, not a missing reference (see `.vibe/decisions/024-blank-frame-sentinel-accepts-any-negative-value.md`, superseding `013`).
**Files:** `air/animation.go`, `air/parser.go`, `air/serializer.go`, `air/document.go`, `air/resolve.go`
**Exports:** `Animation` (struct, `json:"..."`-tagged), `Frame` (struct, `json:"..."`-tagged) with `(Frame) IsBlank() bool`, `ClsnBox` (struct, `json:"..."`-tagged), `Flip` (string type) with constants `FlipNone`, `FlipH`, `FlipV`, `FlipHV`, `BlendMode` (string type), `Parse(r io.Reader) ([]Animation, error)`, `Serialize(w io.Writer, animations []Animation) error`, `Document` (struct), `ParseDocument(r io.Reader) (*Document, error)`, `(*Document) Serialize(w io.Writer) error`, `SpriteResolver` (struct), `NewSpriteResolver(groups []sff.SpriteGroup) *SpriteResolver`, `(*SpriteResolver) Resolve(frame Frame) (sff.Sprite, error)`
**Depends on:** the external `github.com/openkakutou/sff` module (via `SpriteResolver`, which resolves `Frame` references against `sff.Sprite`/`sff.SpriteGroup` — no longer an in-repo sub-package, see item 035)
