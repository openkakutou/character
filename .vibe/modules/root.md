# Module: root

**Role:** Entry point of the library. Assembles the `air`/`def`/`sff` sub-packages into a single `Character` struct — the unit a library consumer actually works with — and exposes both frame-to-sprite resolution and a full `.def`-driven load directly on/around it. `cns` is not yet implemented, so `Character` has no field for it yet.
**Files:** `character.go`, `load.go`
**Exports:** `Character` (struct: `Name string`, `Animations []air.Animation`, `Sprites []sff.SpriteGroup`), `(*Character) ResolveSprite(frame air.Frame) (sff.Sprite, error)`, `Load(path string) (*Character, error)`
**Depends on:** `modules/air.md` (for `air.Animation`/`air.Frame`/`air.Parse` and to delegate resolution to `air.NewSpriteResolver`), `modules/def.md` (for `def.Parse`/`def.CharacterInfo`), `modules/sff.md` (for `sff.SpriteGroup`/`sff.Sprite`/`sff.Load`)

**Design decision:** `ResolveSprite` does not reimplement frame-to-sprite lookup — it builds an `air.SpriteResolver` from `c.Sprites` and delegates to it, keeping that logic owned by `character/air` (per `.vibe/decisions/008-air-sprite-resolution-lives-in-air-package.md`). Only `air`/`sff` read-path types are reachable from `Character`; no write-only (format-preservation) type is exposed. `Load` is the library's top-level "load a real character" entry point: it opens the `.def` file at `path`, parses it with `def.Parse`, resolves the `.air`/`.sff` paths it references against `path`'s own directory (matching real MUGEN/Ikemen character folder layout), reads them with `air.Parse`/`sff.Load`, and returns the assembled `Character`; a missing or unreadable file at any step returns a descriptive error naming which file and step failed, rather than panicking. See `.vibe/decisions/010-def-loader-assembles-character-from-referenced-files.md`.
