# Module: root

**Role:** Entry point of the library. Assembles the `air`/`def`/`cns` sub-packages, plus the external `github.com/openkakutou/sff` module, into a single `Character` struct — the unit a library consumer actually works with — and exposes both frame-to-sprite resolution and two full-load entry points directly on/around it: `Load` (from a `.def` file path, filesystem-based) and `LoadBytes` (from already-in-memory byte buffers, filesystem-independent — the shape a browser/WASM caller needs). This completes the full read surface across all four MUGEN/Ikemen file formats.
**Files:** `character.go`, `load.go`, `load_bytes.go`
**Exports:** `Character` (struct: `Name string`, `Animations []air.Animation`, `Sprites []sff.SpriteGroup`, `StateDefs []cns.StateDef` — all `json:"..."`-tagged), `(*Character) ResolveSprite(frame air.Frame) (sff.Sprite, error)`, `Load(path string) (*Character, error)`, `LoadBytes(defBytes, airBytes, sffBytes, cnsBytes []byte) (*Character, error)`
**Depends on:** `modules/air.md` (for `air.Animation`/`air.Frame`/`air.Parse` and to delegate resolution to `air.NewSpriteResolver`), `modules/def.md` (for `def.Parse`/`def.CharacterInfo`), the external `github.com/openkakutou/sff` module (for `sff.SpriteGroup`/`sff.Sprite`/`sff.Load` — no longer an in-repo sub-package, see item 035), `modules/cns.md` (for `cns.StateDef`/`cns.Parse`)

**Design decision:** `ResolveSprite` does not reimplement frame-to-sprite lookup — it builds an `air.SpriteResolver` from `c.Sprites` and delegates to it, keeping that logic owned by `character/air` (per `.vibe/decisions/008-air-sprite-resolution-lives-in-air-package.md`). Only `air`/`sff`/`cns` read-path types are reachable from `Character`; no write-only (format-preservation) type is exposed. `Load` is the library's top-level "load a real character from disk" entry point: it opens the `.def` file at `path`, parses it with `def.Parse`, resolves the `.air`/`.sff`/`.cns` paths it references against `path`'s own directory (matching real MUGEN/Ikemen character folder layout), reads them with `air.Parse`/`sff.Load`/`cns.Parse`, and returns the assembled `Character`; a missing or unreadable file at any step returns a descriptive error naming which file and step failed, rather than panicking. See `.vibe/decisions/010-def-loader-assembles-character-from-referenced-files.md`. `LoadBytes` is `Load`'s filesystem-independent counterpart, added for `cmd/wasm` (see `modules/wasm.md`): it parses each of the four byte buffers directly (`bytes.NewReader` into `def.Parse`/`air.Parse`/`sff.Load`/`cns.Parse`), never resolving or following the `.def` file's own referenced paths — the caller already supplies the right bytes for each format. It also normalizes every slice/map reachable from the returned `Character` to non-`nil` before returning, so `encoding/json` always renders an empty collection as `[]`/`{}`, never `null` — a JSON/JS-boundary guarantee specific to this function, not retrofitted onto `Parse`/`Load`'s ordinary Go-idiomatic nil slices. See `.vibe/decisions/019-wasm-entrypoint-byte-buffer-loading-and-json-contract.md`.
