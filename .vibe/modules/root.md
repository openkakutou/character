# Module: root

**Role:** Entry point of the library. Assembles the `air`/`def`/`cns` sub-packages, plus the external `github.com/openkakutou/sff` module, into a single `Character` struct — the unit a library consumer actually works with — and exposes both frame-to-sprite resolution and two full-load entry points directly on/around it: `Load` (from a `.def` file path, filesystem-based) and `LoadBytes` (from already-in-memory byte buffers, filesystem-independent — the shape a browser/WASM caller needs). This completes the full read surface across all four MUGEN/Ikemen file formats.
**Files:** `character.go`, `load.go`, `load_bytes.go`, `save.go`
**Exports:** `Character` (struct: `Name string`, `Author string`, `SpriteFile string`, `AnimationFile string`, `SoundFile string`, `CommandFile string`, `ConstantsFile string`, `StateFiles []string`, `Palettes []string`, `Animations []air.Animation`, `Sprites []sff.SpriteGroup`, `StateDefs []cns.StateDef` — all `json:"..."`-tagged), `(*Character) ResolveSprite(frame air.Frame) (sff.Sprite, error)`, `Load(path string) (*Character, error)`, `LoadBytes(defBytes, airBytes, sffBytes, cnsBytes []byte) (*Character, error)`, `SerializeDef(original []byte, info def.CharacterInfo) ([]byte, error)`, `SerializeAir(original []byte, animations []air.Animation) ([]byte, error)`, `SerializeCns(original []byte, states []cns.StateDef) ([]byte, error)`, `SerializeCmd(original []byte, file cmd.CommandFile) ([]byte, error)`, `SerializeZss(original []byte, script zss.Script) ([]byte, error)`
**Depends on:** `modules/air.md` (for `air.Animation`/`air.Frame`/`air.Parse` and to delegate resolution to `air.NewSpriteResolver`), `modules/def.md` (for `def.Parse`/`def.CharacterInfo`), the external `github.com/openkakutou/sff` module (for `sff.SpriteGroup`/`sff.Sprite`/`sff.Load` — no longer an in-repo sub-package, see item 035), `modules/cns.md` (for `cns.StateDef`/`cns.Parse`), `modules/cmd.md` (for `cmd.CommandFile`/`cmd.ParseDocument`/`cmd.Serialize`, item 039), `modules/zss.md` (for `zss.Script`/`zss.ParseDocument`/`zss.Serialize`, item 039)

**Design decision:** `ResolveSprite` does not reimplement frame-to-sprite lookup — it builds an `air.SpriteResolver` from `c.Sprites` and delegates to it, keeping that logic owned by `character/air` (per `.vibe/decisions/008-air-sprite-resolution-lives-in-air-package.md`). Only `air`/`sff`/`cns` read-path types are reachable from `Character`; no write-only (format-preservation) type is exposed. `Load` is the library's top-level "load a real character from disk" entry point: it opens the `.def` file at `path`, parses it with `def.Parse`, resolves the `.air`/`.sff`/`.cns` paths it references against `path`'s own directory (matching real MUGEN/Ikemen character folder layout), reads them with `air.Parse`/`sff.Load`/`cns.Parse`, and returns the assembled `Character`; a missing or unreadable file at any step returns a descriptive error naming which file and step failed, rather than panicking. See `.vibe/decisions/010-def-loader-assembles-character-from-referenced-files.md`. `Load` resolves each referenced path through a shared `resolveReferencedPath(dir, referenced string) string` helper, not a bare `filepath.Join`: it normalizes Windows-style backslash separators in the referenced string (real `.def` files are Windows-authored, where a backslash is unambiguously a separator, never literal filename data) to forward slashes before joining, so a reference like `states\constants.cns` correctly resolves into a nested subdirectory on a forward-slash filesystem (Linux, and the WASM/browser target) instead of being treated as one literal filename and failing with "no such file or directory" — the single largest cause of real-character load failures found in a corpus scan (item 049). `dir` itself (derived from `Load`'s own Go-native `path` argument, not from `.def` content) is left unnormalized, since it is already in the host's native convention. Opening each resolved path also now goes through a shared `openReferencedFile(dir, referenced string) (*os.File, error)` helper rather than a bare `os.Open`: it tries the exact-case path first (a single `os.Open`, no extra cost for the common case), and only when that returns not-exist does it fall back to `resolveCaseInsensitive(base, relPath string) (string, bool)`, which walks the referenced path component by component, matching each component against the actual on-disk directory entries case-insensitively via `os.ReadDir` when no exact match exists — real `.def` files are Windows-authored, where filesystem paths are case-insensitive, and many reference a file under different letter casing than its actual on-disk name (e.g. `Kyoxiii.air` referencing an on-disk `KyoXIII.air`), the second-largest cause of real-character load failures found in the same corpus scan (item 050). When no case-insensitive match exists either, the original exact-case `os.Open` error is returned unchanged, preserving the existing descriptive "no such file or directory"-style error. `LoadBytes` is `Load`'s filesystem-independent counterpart, added for `cmd/wasm` (see `modules/wasm.md`): it parses each of the four byte buffers directly (`bytes.NewReader` into `def.Parse`/`air.Parse`/`sff.Load`/`cns.Parse`), never resolving or following the `.def` file's own referenced paths — the caller already supplies the right bytes for each format. It also normalizes every slice/map reachable from the returned `Character` to non-`nil` before returning, so `encoding/json` always renders an empty collection as `[]`/`{}`, never `null` — a JSON/JS-boundary guarantee specific to this function, not retrofitted onto `Parse`/`Load`'s ordinary Go-idiomatic nil slices. See `.vibe/decisions/019-wasm-entrypoint-byte-buffer-loading-and-json-contract.md`. `Load` also now validates, right after `def.Parse` succeeds, that at least one of `AnimationFile`/`SpriteFile`/`ConstantsFile` is non-empty via `validateFilesSection(path, info)`, before resolving/opening any referenced path. A `.def` with no `[Files]` section at all — most commonly an Ikemen GO storyboard/intro/ending screen definition (a `[SceneDef]`/`[Scene N]`-based file, an entirely different sub-format) sitting inside a character's own folder — parses successfully per `def.Parse`'s own documented "skip unrecognized sections" contract, but leaves `CharacterInfo` at its zero value; left unchecked, an empty referenced path resolves to the `.def`'s own containing directory (`filepath.Join(dir, "")`) and fails with an opaque "is a directory" filesystem error instead of naming the real problem. `validateFilesSection` returns a clear error naming the `.def` path and stating it doesn't look like a character definition instead. A `.def` missing only some `[Files]` entries (e.g. no `cns`) is untouched by this check and still surfaces the existing per-file "opening ... file" error further down `Load`. See backlog item 051. Both `Load` and `LoadBytes` now thread every field of the parsed `def.CharacterInfo` onto the returned `Character` — not just `Name` — so `Author` and every referenced file path (`SpriteFile`/`AnimationFile`/`SoundFile`/`CommandFile`/`ConstantsFile`/`StateFiles`/`Palettes`) reach a WASM/JS consumer's JSON contract the same way `Animations`/`Sprites`/`StateDefs` already do; these fields are metadata carried over as-is from the `.def` file, never used by either function to locate the animations/sprites/state defs, which are already supplied directly (`LoadBytes`) or resolved via the existing path-resolution helpers above (`Load`). `LoadBytes`'s existing JSON-normalization pass (`normalizeForJSON`) now also defaults a `nil` `StateFiles`/`Palettes` to an empty slice, matching its existing guarantee for every other collection on `Character`. See backlog item 038.

`save.go` (item 039) adds the write-path counterpart: `SerializeDef`/`SerializeAir`/`SerializeCns`/`SerializeCmd`/`SerializeZss`, one per format, each taking that format's own previously loaded bytes (empty for a brand new file with no original yet) plus the current in-memory model. Each reuses the two write paths the format-specific packages already have rather than inventing a third: when the model, once normalized (nil slices/maps treated as their non-nil empty equivalent — `normalizeCharacterInfoForJSON`/`normalizeAnimationsForJSON`/`normalizeStateDefsForJSON`/`normalizeCommandFileForJSON`/`normalizeScriptForJSON`, the last two new, the middle two reusing `load_bytes.go`'s existing per-element normalizers across a whole slice), deep-equals what parsing `original` itself produces (also normalized), the original bytes are written back out verbatim via that format's `Document` — byte-exact; otherwise (a real edit, or `original` empty) fresh text comes from that format's own `Serialize`. `.cmd`/`.zss` are deliberately not wired into `Character`/`LoadBytes`'s JSON contract by this item — `SerializeCmd`/`SerializeZss` take `cmd.CommandFile`/`zss.Script` directly, independent of `Character` — since a character uses `.cns` or `.zss` never both, and every write-path consumer works one format at a time. See `.vibe/decisions/028-wasm-save-path-per-format-diff-or-serialize.md`.
