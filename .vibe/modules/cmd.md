# Module: cmd

**Role:** MUGEN/Ikemen GO input command (`.cmd`) files — a character's named input commands (motion + button sequences), their recognition timing, optional button remapping, and their link to the "always" state that reacts to them. Provides the pure-data model (`CommandFile`, `CommandDefaults`, `Command`), a read-path text parser (`Parse`), a `Serialize` write path, and a `Document`/`ParseDocument` pair for byte-exact round trips of unmodified files. `.cmd`'s `[Statedef -1]`/`[State ...]` block is not reimplemented here: it shares `.cns`'s syntax byte-for-byte, so `Parse`/`Serialize` delegate that part to `cns.Parse`/`cns.Serialize` directly against the same source text, synthesizing an implicit `[Statedef -1]` header first when a real-world file omits it entirely. Not yet wired into the root `Character` struct.

**Files:** `cmd/command.go`, `cmd/parser.go`, `cmd/serializer.go`, `cmd/document.go`

**Exports:**
- `CommandFile` (struct, `json:"..."`-tagged: `Remap map[string]string`, `Defaults CommandDefaults`, `Commands []Command`, `States []cns.StateDef`) — a `.cmd` file's full contents: optional button remapping, file-level recognition defaults, the named input commands, and the linked state-controller block (parsed via `cns`, not a dedicated type)
- `CommandDefaults` (struct, `json:"..."`-tagged: `Time int`, `BufferTime int`) — file-level `command.time`/`command.buffer.time` a `Command` falls back to when it doesn't set its own
- `Command` (struct, `json:"..."`-tagged: `Name string`, `Input string`, `Time int`, `BufferTime int`) — a single `.cmd [Command]` section; `Input` is the raw, unevaluated input-sequence expression (e.g. `"~D, DF, F, a"`), stored verbatim rather than decomposed — this package has no input-sequence grammar, mirroring `cns.Controller`'s own unevaluated `Triggers`/`Parameters`; `Time`/`BufferTime` at zero mean "not set, use `CommandFile.Defaults`"
- `Parse(r io.Reader) (CommandFile, error)` — reads `.cmd` text into a `CommandFile`; the `[Remap]`/`[Defaults]`/`[Command]` sections (matched case-insensitively) populate `Remap`/`Defaults`/`Commands`, while `[Statedef -1]`/`[State ...]` is left for a delegated `cns.Parse` call into `States`. A bracket line missing its closing `]` that looks like an attempt at one of this package's own three headers returns a line-numbered "malformed section header" error; any other bracket line missing `]` (e.g. a `[State ...]` header — a real-world `.cmd` authoring typo, mirroring `.cns`'s own item 042) is left for `cns.Parse`'s own recovery instead. Real-world `.cmd` files sometimes omit the `[Statedef -1]` header entirely, since `-1` is the only Statedef number a `.cmd` "always" section can ever use — `Parse` synthesizes it before delegating to `cns.Parse` when the source declares no `[Statedef ...]` header of its own (found via a real-character corpus scan: Marvel's "Jean Grey" and "Nova"; see `.vibe/decisions/026-cmd-parse-synthesizes-implicit-statedef-minus-1-header.md`). A content line inside a known section that isn't a valid `key=value` pair is ignored, the same tolerance `def.Parse`/`cns.Parse` already apply. See `.vibe/decisions/025-cmd-package-reuses-cns-for-state-triggering-block.md`.
- `Serialize(w io.Writer, file CommandFile) error` — writes a `CommandFile` back out as `.cmd` text: a `[Remap]` section (only if non-empty), a `[Defaults]` section (only if non-zero), one `[Command]` block per entry, then the linked state via `cns.Serialize`; a semantic round trip through `Parse`, not byte-exact preservation. A `Command`'s `Time`/`BufferTime` is only written when non-zero, so an unset override never round-trips into an explicit `0`.
- `Document`/`ParseDocument(r io.Reader) (*Document, error)` — format-preserving write-path counterpart to `Parse`/`Serialize`, mirroring `air`/`def`/`cns`'s own `Document` split (see `.vibe/decisions/003-air-round-trip-via-separate-document-type.md`): `ParseDocument` decodes `File` the same way `Parse` does while retaining the exact source bytes; `(*Document).Serialize(w io.Writer) error` replays those bytes verbatim.

Validated against a 520-file real-character corpus: 99.8% parse successfully; the one remaining failure is a pre-existing gap in `cns.Parse` itself (a decorative, unclosed `[` line unrelated to `.cmd`), tracked separately as backlog item 053 rather than fixed here.

**Depends on:** `cns` (delegates its `[Statedef -1]`/`[State ...]` block parsing/serialization directly to `cns.Parse`/`cns.Serialize`)
