# Module: sff

**Role:** MUGEN/Ikemen GO sprite (`.sff`) files. `sprite.go` defines `Sprite` and `SpriteGroup` — the stable, version-agnostic read-path vocabulary a library consumer (editor, engine) works with (no v1/v2-specific fields), since `.sff` has two on-disk versions with different header layouts and pixel encodings that both need to populate the same shape. `v1.go` adds `ParseV1`, a binary reader for the v1 file header and sprite index table: it resolves each sprite's `(Group, Image)` key to the file offset/length of its pixel data, but does not decode that pixel data and does not populate `Sprite`/`SpriteGroup` directly — see the module's design decision below. `pcx.go` adds `DecodePCX`, decoding the RLE-compressed 8-bit indexed PCX pixel data v1 sprites use (the byte range `ParseV1` located) into a pure pixel index buffer plus the dimensions recovered from the PCX data's own embedded header. `pcx_encoder.go` adds `EncodePCX`, the write-path counterpart of `DecodePCX`: RLE-encodes a pixel buffer back into PCX bytes, always as run-length units (never a bare literal), padding an odd width's scanlines to an even `bytesPerLine`. `v1_serializer.go` adds `SerializeV1`, the write-path counterpart of `ParseV1`: writes a full v1 file (header + subheader + pixel data per sprite) from a `V1WriteSprite` slice, deriving the header's group/image counts from the input rather than trusting a caller-supplied count, and validating `LinkedIndex` (in range, not self-referencing) for sprites written without their own pixel data. `v2.go` adds `ParseV2`, a binary reader for the v2 (Ikemen-compatible) file header and its sprite and palette index tables: unlike v1's linked-list subfile chain, v2's tables are flat, fixed-size-record arrays addressed directly by the header's declared table offsets, and each sprite's pixel-data offset is resolved against one of two file-level data section bases (`literal`/`translated`) depending on a per-sprite on-disk flag bit. `ParseV2` locates sprite pixel data and palette bank color data (offset/length) but does not decode either — the v2 pixel decoder (item 011) is not yet implemented, and there is no v2 write path yet.
**Files:** `sff/sprite.go`, `sff/v1.go`, `sff/pcx.go`, `sff/pcx_encoder.go`, `sff/v1_serializer.go`, `sff/v2.go`
**Exports:** `Sprite` (struct: `Group`, `Image`, `Width`, `Height`, `AxisX`, `AxisY`, `Palette`), `SpriteGroup` (struct: `Index`, `Sprites []Sprite`), `ParseV1(r io.ReaderAt) (*V1SpriteTable, error)`, `V1Header` (struct: `Version [4]byte`, `GroupCount`, `ImageCount`, `SharedPalette`), `V1SpriteEntry` (struct: `Group`, `Image`, `AxisX`, `AxisY`, `Offset int64`, `Length`, `LinkedIndex`, `SharedPalette`), `V1SpriteTable` (struct: `Header V1Header`, `Sprites []V1SpriteEntry`; method `Offset(group, image int) (int64, bool)`), `DecodePCX(data []byte) (*PCXImage, error)`, `PCXImage` (struct: `Width`, `Height int`, `Pixels []byte`), `EncodePCX(img *PCXImage) ([]byte, error)`, `SerializeV1(w io.Writer, version [4]byte, sharedPalette bool, sprites []V1WriteSprite) error`, `V1WriteSprite` (struct: `Group`, `Image`, `AxisX`, `AxisY`, `SharedPalette`, `PixelData []byte`, `LinkedIndex`), `ParseV2(r io.ReaderAt) (*V2SpriteTable, error)`, `V2Header` (struct: `Version [4]byte`, `SpriteCount`, `PaletteCount`), `V2SpriteEntry` (struct: `Group`, `Image`, `Width`, `Height`, `AxisX`, `AxisY`, `Offset int64`, `Length`, `LinkedIndex`, `Format`, `ColorDepth`, `PaletteIndex`), `V2PaletteEntry` (struct: `Group`, `Number`, `ColorCount`, `Offset int64`, `Length`, `LinkedIndex`), `V2SpriteTable` (struct: `Header V2Header`, `Sprites []V2SpriteEntry`, `Palettes []V2PaletteEntry`; methods `Offset(group, image int) (int64, bool)`, `PaletteOffset(group, number int) (int64, bool)`), `V2FormatRaw`/`V2FormatRLE8`/`V2FormatRLE5`/`V2FormatLZ5`/`V2FormatPNG8`/`V2FormatPNG24`/`V2FormatPNG32` (pixel-format code constants)
**Depends on:** none

**Design decision:** `ParseV1`'s output is a separate low-level type (`V1SpriteTable`/`V1SpriteEntry`), not the public `Sprite`/`SpriteGroup` model — it carries a file offset/length that model has no field for, and lacks `Width`/`Height`, only knowable once pixel data is decoded. See `.vibe/decisions/004-sff-v1-table-is-a-separate-low-level-type.md`. `DecodePCX` follows the same pattern: it returns a `PCXImage` (pixel buffer + dimensions), not a populated `Sprite` — folding a decoded sprite's pixels into the public model (with a resolved palette) is left to a later assembly step. On the write side, `SerializeV1` takes its own write-only input type (`V1WriteSprite`) rather than reusing `V1SpriteEntry` (whose `Offset`/`Length` are read-time facts, not writer inputs), and — unlike `air`'s `Document` type — does not attempt a byte-exact round trip of an original file: `.sff` is binary with no diff-friendliness benefit to preserving one, so round-trip fidelity is verified semantically (serialize → re-parse → re-decode → compare). See `.vibe/decisions/005-sff-v1-serialize-is-semantic-not-byte-exact-round-trip.md`. `ParseV2` follows the same low-level-type pattern as `ParseV1` (`V2SpriteTable`/`V2SpriteEntry`/`V2PaletteEntry`, not `Sprite`/`SpriteGroup`), for the same reasons, plus a v2-specific one: v2 additionally needs a palette bank table (`V2PaletteEntry`), which v1's simpler per-sprite/shared palette flag has no equivalent of.
