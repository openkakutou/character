# Module: sff

**Role:** MUGEN/Ikemen GO sprite (`.sff`) files. `sprite.go` defines `Sprite` and `SpriteGroup` — the stable, version-agnostic read-path vocabulary a library consumer (editor, engine) works with (no v1/v2-specific fields), since `.sff` has two on-disk versions with different header layouts and pixel encodings that both need to populate the same shape. `v1.go` adds `ParseV1`, a binary reader for the v1 file header and sprite index table: it resolves each sprite's `(Group, Image)` key to the file offset/length of its pixel data, but does not decode that pixel data and does not populate `Sprite`/`SpriteGroup` directly — see the module's design decision below. `pcx.go` adds `DecodePCX`, decoding the RLE-compressed 8-bit indexed PCX pixel data v1 sprites use (the byte range `ParseV1` located) into a pure pixel index buffer plus the dimensions recovered from the PCX data's own embedded header. The v2 header/table parser (item 010) and its pixel decoder (item 011) are not yet implemented.
**Files:** `sff/sprite.go`, `sff/v1.go`, `sff/pcx.go`
**Exports:** `Sprite` (struct: `Group`, `Image`, `Width`, `Height`, `AxisX`, `AxisY`, `Palette`), `SpriteGroup` (struct: `Index`, `Sprites []Sprite`), `ParseV1(r io.ReaderAt) (*V1SpriteTable, error)`, `V1Header` (struct: `Version [4]byte`, `GroupCount`, `ImageCount`, `SharedPalette`), `V1SpriteEntry` (struct: `Group`, `Image`, `AxisX`, `AxisY`, `Offset int64`, `Length`, `LinkedIndex`, `SharedPalette`), `V1SpriteTable` (struct: `Header V1Header`, `Sprites []V1SpriteEntry`; method `Offset(group, image int) (int64, bool)`), `DecodePCX(data []byte) (*PCXImage, error)`, `PCXImage` (struct: `Width`, `Height int`, `Pixels []byte`)
**Depends on:** none

**Design decision:** `ParseV1`'s output is a separate low-level type (`V1SpriteTable`/`V1SpriteEntry`), not the public `Sprite`/`SpriteGroup` model — it carries a file offset/length that model has no field for, and lacks `Width`/`Height`, only knowable once pixel data is decoded. See `.vibe/decisions/004-sff-v1-table-is-a-separate-low-level-type.md`. `DecodePCX` follows the same pattern: it returns a `PCXImage` (pixel buffer + dimensions), not a populated `Sprite` — folding a decoded sprite's pixels into the public model (with a resolved palette) is left to a later assembly step.
