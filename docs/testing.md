# Testing

## Running the suite

```sh
go test ./...
```

Lint (run alongside tests, part of this project's definition of done):

```sh
gofmt -l .
go vet ./...
```

## Conventions

- Tests are co-located with source: `*_test.go` alongside the file it
  tests (e.g. `air/parser_test.go` next to `air/parser.go`), one test file
  per source file.
- Test names describe behavior, not implementation:
  `TestParse_MultiActionSample_ProducesExpectedAnimations`, not
  `TestParse`.
- Every unit of behavior is covered by: the nominal path, at least two
  edge cases, and an error/invalid-input path.
- Round-trip tests (serialize → parse → same result) are required for any
  write-path code (`.air`/`.cns`). `air.Serialize` has this today, checked
  against `air.Parse` (semantic round trip: equivalent `Animation`/`Frame`
  data, not byte-exact text). `air.Document` has a separate, byte-exact
  round-trip suite: parsing a realistic fixture and serializing it back
  reproduces the file exactly, comments included, plus edge cases (no
  trailing newline, comment/blank-only file, CRLF line endings) and error
  paths (a failing reader, malformed content). `def.Serialize` has the
  same semantic round-trip treatment, checked against `def.Parse`.
  `def.Document` has a separate, byte-exact round-trip suite, mirroring
  `air.Document`: parsing a realistic fixture and serializing it back
  reproduces the file exactly, comments, section ordering, and unrecognized
  sections included. `cns.Serialize` has the same semantic round-trip
  treatment, checked against `cns.Parse` (including a controller with no
  triggers and a `Statedef` with no controllers). `cns.Document` has a
  separate, byte-exact round-trip suite, mirroring `air.Document`/
  `def.Document`: parsing the realistic fixture (`cns/testdata/sample.cns`)
  and serializing it back reproduces the file exactly, comments, block
  ordering, and the unrecognized `[Data]` section included.

## What's covered today

| Package | What the tests check |
|---|---|
| `character` | The root `Character` struct's zero value; assembling `Animations`/`Sprites` from a real `.air` fixture (`air/testdata/sample.air`, via `air.Parse`) and a matching hand-built sprite collection, checking `ResolveSprite` returns the correct `sff.Sprite` (against distinguishing metadata, not just non-zero output) for every frame of a multi-frame animation; edge cases: `ResolveSprite` returning a descriptive error for a frame referencing a sprite absent from the loaded sprites, and the same on a zero-value `Character` (no sprites loaded at all). `Load` against a real, on-disk `.def`/`.air`/`.sff`/`.cns` fixture folder it builds itself (`.sff` via `sff.SerializeV1`), checking the returned `Character`'s name, animations, sprites, and `StateDefs` (state number, move type, and controller) are correct and that every loaded frame resolves against the loaded sprites via `ResolveSprite`; error paths: the referenced `.air` file missing, the referenced `.sff` file missing, the referenced `.cns` file missing, and the `.def` file itself missing — each returning a descriptive error rather than panicking |
| `character/air` | `SpriteResolver`: every `Frame` in a multi-frame, multi-group animation resolving to its correct `sff.Sprite` (checked against distinguishing metadata, not just non-zero output); an ambiguous-looking `(group, image)` pair (a group/image value each individually present elsewhere) correctly failing rather than cross-matching; a resolver built from `nil`/empty sprite groups; a resolver working the same against sprites carrying v2-only concepts (a non-zero palette bank index) to document version-independence; error path: a descriptive error naming the missing `(group, image)` for a frame with no matching sprite. `Animation`/`Frame`/`ClsnBox` zero values and field assignment; `Parse` against a multi-action `.air` sample (action numbers, frame sequences, `Clsn1Default`/`Clsn2Default` resolution, one-shot `Clsn1:`/`Clsn2:` overrides, the `Loopstart` marker, optional flip/blend fields), an action with no frames, multiple default Clsn boxes; edge cases and error paths: empty and comment-only input, whole-line/trailing comments mixed with valid data, a malformed action header (as the first line and mid-file), missing/non-numeric frame fields, any negative group/image index parsed as the blank-frame sentinel (not range-restricted) alongside negative X/Y/time (also accepted), and a failing reader; `Serialize` round-tripped through `Parse` for a multi-action animation, per-frame Clsn boxes, and the `Loopstart` marker (mid-animation and pointing past the last frame); edge cases and error paths: optional Flip/Blend fields omitted when unset, an empty animation list producing empty output, and a failing writer returning an error instead of panicking; `ParseDocument`/`Document.Serialize` round-tripped byte-for-byte against a realistic multi-action fixture (`air/testdata/sample.air`), asserting both the decoded `Animations` (no lost frames/Clsn boxes/`Loopstart`) and that every comment in the fixture survives in the output; edge cases: a file with no trailing newline, a comment/blank-only file, CRLF line endings, and mutating `Animations` after parsing not affecting `Serialize`'s output; error paths: a failing reader, malformed content, and a failing writer |
| `character/def` | `CharacterInfo` zero value (all string fields empty, nil `StateFiles`/`Palettes` safe to range over) and field assignment (all fields, including multi-entry `StateFiles`/`Palettes`, preserve their assigned order); edge cases: two `CharacterInfo` instances built with their own slice literals don't share underlying `StateFiles`/`Palettes` storage, and a minimal instance (only `Name`/`SpriteFile` set) leaves every other field at its zero value rather than requiring a placeholder. `Parse` against a multi-section `.def` sample (name, author, every `[Files]` reference, `StateFiles` in file-appearance order, `Palettes` sorted by number despite appearing out of order in the source); edge cases and error paths: an unrecognized section (`[Arcade]`) skipped without aborting the sections around it, case-insensitive section names/keys with both quoted and unquoted values, comment lines and blank lines ignored, an unrecognized key inside a known section ignored, empty input returning a zero-value `CharacterInfo`, a malformed `key=value` line and a malformed section header each reporting the offending line number, and a failing reader returning a wrapped error |
| `character/cns` | `StateDef`/`Controller` zero values (all fields zero, nil `Controllers`/`Triggers`/`Parameters`/`HeaderExprs` safe to range over and to look up on) and field assignment (a `StateDef` with multiple controllers, and a controller with no `Triggers` documented as running unconditionally, not "never"). `Parse` against a realistic multi-Statedef `.cns` fixture (`cns/testdata/sample.cns`, covering `Statedef`/`State` header parameters, multiple controllers per state, triggers spread across `trigger1`/`trigger2`/`triggerall` keys in file order, and parameter values preserved verbatim including embedded commas); edge cases: empty input returning an empty result, an unrecognized section (e.g. `[Data]`) between two `Statedef` blocks skipped without aborting, a `Statedef` with zero controllers, a controller with no trigger lines, a `[State ...]` header with no state number attaching correctly to the enclosing `Statedef` (real-world authoring style), and a numeric header field (`anim`/`poweradd`) holding a MUGEN trigger expression or plain-garbage text — both stored verbatim in `HeaderExprs` with the typed field left at zero rather than erroring; a `[Statedef ...]`/`[State ...]` header (numbered and bare-label forms) missing its closing `]` recovering and producing the same data a correctly closed header would, matching real-world files (e.g. the Bardock and Commando characters); a non-key-value content line inside a block (no `=`, e.g. a bare word) ignored rather than erroring, with parsing continuing normally on the well-formed lines around it, matching a real-world file (the Arcana Heart "Aino 2" character); error paths: a `[...]` header missing its closing `]` with no recognizable `statedef`/`state` keyword, a malformed `Statedef` header (non-numeric or missing state number), a `[State ...]` block with no enclosing `Statedef`, an invalid boolean value for a header field (`ctrl`), and a failing reader. `Serialize` checked against an exact expected-text assertion for a single `Statedef` with one controller, then round-tripped through `Parse` for a multi-`Statedef` set covering a negative state number, a `Statedef` with zero controllers, and an unconditional controller (no triggers); a `StateDef` with `HeaderExprs` entries round-tripped through `Parse`, confirming the raw expression text is written verbatim and recovered unchanged; edge cases and error paths: a `Statedef` with zero controllers omits any `[State N]` section, a nil input produces empty output, and a failing writer returns a wrapped error instead of panicking. `ParseDocument`/`Document.Serialize` round-tripped byte-for-byte against the realistic fixture (`cns/testdata/sample.cns`), asserting both the decoded `StateDefs` and that every comment and the unrecognized `[Data]` section survive in the output; edge cases: empty input, and mutating `StateDefs` after parsing not affecting `Serialize`'s output; error paths: a failing reader and malformed content |

Sprite (`.sff`) parsing itself is no longer tested in this repo — that
suite now lives in [`github.com/openkakutou/sff`](https://github.com/openkakutou/sff)'s
own repo. What remains here is how `character`/`air` consume that
module's public API (`sff.Load`, `sff.SpriteGroup`, `sff.Sprite`),
covered by the `character` and `character/air` rows above.
